# Rubo Arena: Голодные игры

Браузерная 3D игра на `Three.js` + `Node.js` в стиле Roblox (low-poly / blocky), с PvPvE механикой:
- игрок против NPC и зомби,
- лут из сундуков,
- фазовое сужение зоны,
- рандомные события матча,
- поддержка ПК и смартфонов,
- отдельные сборки `single` и `multi`.

---

## 1. Что это за проект

`Rubo Arena` — арена на выживание:
- старт игроков на спавне,
- фаза безопасности,
- затем зона сжимается,
- побеждает последний выживший.

В проекте есть единая кодовая база в корне и сборка под публикацию в Яндекс Игры:
- `single/` — одиночный режим (с ботами и PvE),
- `multi/` — клиент мультиплеера (WebSocket-синхронизация).

## 6. Как устроен рантайм

## 6.1 Инициализация (`main.js`)

Создаются и связываются подсистемы:
- `Scene`, `Camera`, `Renderer`,
- `Input`, `HUD`, `AudioSynth`,
- `MapGenerator`, `Physics`, `Zone`, `Environment`,
- `EntityManager`, `LootManager`,
- `Player`, `Bot[]`, `Zombie[]`.

Игровой цикл делится на:
- update состояния,
- update сущностей/ботов/зомби,
- обработку событий,
- рендер кадра.

## 6.2 Цикл игры (`core/GameLoop.js`)

Классический `requestAnimationFrame`:
- дельта времени,
- вызов `game.update(delta)`,
- рендер.

В коде есть троттлинг тяжёлых операций (боты, POI-спавн, зомби-пакеты), чтобы не ловить фризы.

## 6.3 Физика и коллизии (`world/Physics.js`)

- перемещение по осям с проверкой боксов-коллайдеров,
- поддержка walkable/non-walkable поверхностей,
- учёт высоты поверхности карты.

## 6.4 Сущности и попадания (`entities/EntityManager.js`)

Отвечает за:
- обновление и удаление снарядов,
- line-of-sight проверки,
- попадания в сущности и стены,
- эффекты попаданий,
- spatial index для быстрых nearby-запросов.

## 7. Геймплейные системы

## 7.1 Баланс (`core/GameBalance.js`)

В одном месте хранятся:
- число ботов для desktop/mobile,
- таймеры раунда (countdown, invulnerable),
- параметры зоны (длительность, фазы, радиус),
- параметры событий (в т.ч. радиационный дождь),
- пресеты режимов (`hybrid`, `nightmare`, `stealth`, `classic`).

## 7.2 Карта (`world/MapGenerator.js`)

Процедурно генерирует:
- floor tilemap,
- дома, ангары, домики на деревьях,
- рельсы/поезда,
- биомы, декор, патчи воды/лавы/тумана,
- сундуки и точки интереса.

Важные API:
- `getSpawnPads()`,
- `getChestSpots()`,
- `getHouseSpots()/getHangarSpots()`,
- `findStructureInteriorPoint()/getStructureEntryPoint()`,
- `isShelteredFromRain()`.

## 7.3 Оружие (`items/Weapon.js`)

Содержит:
- профили оружия (урон, дальность, кд, ammo/durability),
- low-poly модели оружия,
- создание снарядов и их параметры,
- отдачу/анимации применения.

Поддерживаемые типы:
- `knife`
- `pistol`
- `rifle`
- `shotgun`
- `machinegun`
- `flamethrower`
- `lasergun` (`laser`)
- `bow`

## 7.4 Лут (`items/LootManager.js`)

- генерация и ресет сундуков,
- защита от конфликтного лута ботов (`claim` механика),
- выдача оружия/брони/патронов.

## 7.5 ИИ ботов (`entities/Bot.js` + `entities/BotBrain.js`)

Текущее поведение:
- лутинг по приоритетам,
- бой с врагами в зоне видимости,
- реакция на зону и события,
- анти-скучивание (separation / stuck reset),
- выбор целей и переключение состояний.

## 7.6 Зомби (`entities/Zombie.js`)

- отдельный вражеский пул,
- спавн вокруг POI (дома/ангары) + ночные усиления,
- атака по игроку и NPC.

## 7.7 События

В матче могут включаться:
- `blindness` (сильное ограничение видимости),
- `night` (ночная фаза, усиление угрозы),
- `radiationRain` (предупреждение + grace + урон вне укрытий).

## 8. Управление

## ПК
- `W A S D` — движение
- `Mouse` — обзор
- `ЛКМ` — удар/выстрел
- `Space` — прыжок
- `E` — взаимодействие
- `1..9,0` — слоты инвентаря
- `P` — меню перков

## Смартфон
- левый виртуальный стик — движение
- правая зона/жест — обзор
- кнопки `ПРЫЖОК`, `УДАР`, `E`
- отдельная кнопка паузы

## 9. Single и Multi

## Single
- основной режим с ботами и зомби,
- полный PvPvE геймплей.

## Multi
- WebSocket синхронизация через `/ws`,
- комнаты по `room` (см. `server.js`),
- state-апдейты игроков и hit-события.

## 10. Подготовка к Яндекс Играм

Генерация папок:
```bash
npm run build:yandex
```

Скрипт:
- очищает `single/` и `multi/`,
- копирует актуальный код из корня,
- инжектит `window.__ARENA_BUILD_MODE` (`single`/`multi`) в `index.html`,
- кладёт `README_YANDEX.txt`.

Важно:
- загружайте в Яндекс **содержимое** папки `single/` или `multi/`,
- не добавляйте в релиз архивы проекта с мусорными файлами,
- проверяйте соответствие названия, языка и медиаматериалов требованиям платформы.

## 11. Производительность

В проекте уже используются:
- spatial index для nearby-поиска,
- частичное обновление тяжёлых подсистем по кадрам,
- пакетный deferred spawn (без пиковых фризов),
- ограничение дальности отображения мелкого декора,
- отключённые тени и адаптивный `pixelRatio` на мобиле.

Если нужна дополнительная оптимизация:
- профилировать `main.js` update-проходы,
- анализировать стоимость AI-тика и projectile-check,
- смотреть GPU-time на мобильных при больших сценах.

## 12. Типовые проблемы

## Локально вижу ошибки Yandex SDK вида `No parent to post message`
Это нормально вне iframe Яндекс Игр. В локальном режиме SDK работает в fallback.

## Игра не запускается из `file://`
Нужен HTTP сервер (`npm start`), так как используются ES-модули и загрузка ассетов.

## MIME ошибки на хостинге
Проверьте сервер: `.js` должен отдаваться как `application/javascript`.
В `server.js` это уже настроено.

## 13. Лицензии и ассеты

- В проекте используются сторонние библиотеки (`three`, `express`, `ws`) по их лицензиям.
- Для любых внешних моделей/звуков обязателен контроль прав использования перед публикацией.
- В `assets/models/weapons/THIRD_PARTY_MODELS.txt` храните источники/атрибуцию, если подключаете внешние модели.

---

## 14. Рекомендованный рабочий процесс

1. Правки делаются в корневом коде (`core`, `entities`, `items`, `world`, `ui`, `main.js`).
2. Локальный тест: `npm start`.
3. Перед публикацией: `npm run build:yandex`.
4. Тест папок `single/` и `multi/` отдельно.
5. Затем только релиз.
